GitHub Pages を使って Space Quiz を公開しましょう。Copilot がワークフローを準備し、デプロイを案内しますが、変更をレビューしてサイトが公開されたことを確認するのはユーザー自身です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages のデプロイを構成させる。
- ワークフローとプルリクエストをレビューしてからマージする。
- デプロイの進行状況を確認し、公開されたサイトを検証する。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、誰でも簡単に試せる場所がまだありません。単一ファイルのサイトを GitHub Pages で公開すると、サーバーや実行時の依存関係を追加せず、公開 URL から利用できるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストを作成すると、コードのコミットとプッシュが行われる場合があります。このプロンプトを送る前に、承認設定と対象リポジトリを確認してください。**Approve all** が有効な場合、別途確認を求められないことがあります。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリに GitHub Pages のデプロイを準備してください。必要であればサイトをビルドし、既定のブランチに変更が反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README が存在しない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更を含むプルリクエストを作成し、そのリンクと、必要な Pages 設定や権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。レビューを待って停止してください。
```

## ワークフローとプルリクエストをレビューする

1. README は、リポジトリに既存の README がない場合にのみ追加されていることを確認します。
2. ビルドとデプロイの手順、トリガー、権限など、プルリクエストに含まれるワークフローの変更をレビューします。
3. ワークフローがマージ前のプルリクエストではなく、既定のブランチからデプロイすることを確認します。
4. 修正が必要な場合は依頼し、更新された差分をレビューします。マージを許可する前に、必要なプルリクエストのチェックが成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトを送信すると、レビュー済みのプルリクエストのマージ、リポジトリ Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認してから送信してください。承認設定によっては、これらの操作に別途確認が求められない場合があります。

`<PR_NUMBER>` をレビューしたプルリクエストの番号に置き換えてから、別のプロンプトとして送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使って GitHub Pages を有効にし、必要なチェックが成功した後にそのプルリクエストだけをマージしてください。デプロイが成功するまで監視し、公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージに権限が必要な場合は、何を承認または実行する必要があるかを正確に説明してください。サイトが公開されるまでは成功と報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイが成功するまで実行状況を確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを実行できない場合は、エージェントが示す手順に従います。デプロイが成功して公開サイトが読み込まれるまでは、作業を完了と判断しないでください。
