最初は小さな機能を追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は組織の既存のワークフローに沿って動作し、適切な方法で適切な機能を構築できるよう支援します。このレッスンから、典型的なエージェント駆動の開発プロセスを始めます。issue を使って機能を作成し、コードの妥当性と機能の動作を確認して、最終的にプロジェクトへマージします。

> [!NOTE]
> 機能の作業を続ける間は、同じ会話とブランチを使います。通常は、扱うファイルの種類ごとに異なるブランチや PR を使いますが、ここでは主な概念に集中するため、一部を簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から新しい Copilot 会話を始める。
- Plan モードで要件を決める。
- Autopilot モードで機能を実装する。
- コードをレビューする。
- 転送されたブラウザーで機能を手動で検証する。

機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して、QA エージェントを作成し、機能 PR を開きます。

## シナリオ

Tailspin Toys のゲームカタログが増えてきたため、訪問者がカテゴリと出版社でゲームを絞り込めるようにします。バックログの issue には機能が説明されていますが、カテゴリを組み合わせる方法など、実装前に合意が必要な詳細もあります。Plan モードで決定し、範囲を明確に定めて Autopilot に実装を依頼します。

## 背景

AI コーディングエージェントを開発ワークフローに導入しても、基本は変わりません。むしろ、より重要になります。多くの開発者は、次のような流れで作業しています。

1. 必要な作業を記述した issue から始める。
2. 構築する内容を計画する。
3. コードを作成してレビューする。
4. テストを実行してコードを検証する。
5. 新しい機能を手動で検証する。
6. プルリクエスト (PR) を作成する。
7. コードがレビューされ、継続的インテグレーションが成功したら、コードをマージする。

> [!NOTE]
> 手順の詳細は、チームや組織によって異なります。多くの場合、上記の流れを調整したものになります。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューと検証を受けるようにできます。

## 会話モード

**会話モード**で、エージェントに任せる自律性の程度を制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと協力して作業します。エージェントは変更を提案し、次の作業に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントは最初に計画を作成します。プロジェクトファイルの編集はできません。
- **Autopilot**: エージェントはコードを書き、テストを実行し、タスクが完了するまで反復して自律的に作業します。

最初に Plan モードで計画を確認し、その後 Autopilot モードで実装します。

## issue から始める

フィルター機能に取り組む前に Codespace に戻り、リポジトリとターミナルの準備を確認します。

1. Codespace に戻ります。停止している場合は再起動します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub 上の issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てることで、機能やタスクの実装を Copilot に任せる前に、その進め方を決められます。複雑な作業では、時間をかけて計画を作ることをお勧めします。Plan モードに切り替えて計画を依頼しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した issue の後に、次のプロンプトを入力します。

   ```plaintext
   この機能の実装計画を作成してください。
   ```

Copilot はプロジェクトを調べ、適切な方法を決めて計画を作成します。

3. フィルター機能の動作について質問された場合は、希望に応じて回答します。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して、計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 希望と異なる部分があれば、Copilot に計画の修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot を使うと、Copilot はタスクが完了したと判断するまで問題に取り組み、反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンに表示される同様のラベルの選択肢を選びます。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が合意済みの計画に沿って作業を進め、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、実装がすぐに始まる場合があります。先に計画をレビューしてください。依存関係が不足している、またはポートが競合していると Copilot が報告した場合は、チェック完了と判断する前にセットアップを修正します。

## 実装をレビューして検証する

他のコードと同様に、生成されたコードもマージ前にレビューします。コードをレビューしてサイトを実行し、問題がないか確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** または **Autopilot** がないことを確認します。
2. `/diff` を入力し、フィルター機能とテストを確認します。
3. issue と計画時に決めた内容に照らし合わせます。
4. コードをレビューしたら <kbd>Esc</kbd> を押して差分表示を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を試す

コードに問題がないことを確認しました。次は、アプリを起動して Codespaces の転送ポートからサイトを開き、実際に動くか確認しましょう。

1. 次のプロンプトで Copilot にアプリの起動を依頼します。

   ```plaintext
   ブラウザーでフィルター機能を試せるようにアプリを起動してください。URL を教え、サーバーは実行したままにしてください。
   ```

2. Codespaces でポート `4321` が利用可能になったら **Open in Browser** を選択します。
3. 計画で決めたカテゴリ、出版社、組み合わせによるフィルターを試します。
4. リセットと該当なしの場合の動作が、issue と合意内容に沿っていることを確認します。
5. Codespace に戻り、Copilot に開発サーバーを停止するよう依頼します。

## まとめと次のステップ

会話モードを使い分けて、機能を実装しレビューしました。このレッスンでは、次のことを行いました。

- GitHub issue から Copilot の会話を開始した。
- Plan モードで要件を決めた。
- Autopilot モードで新機能を実装した。
- コードをレビューした。
- 転送されたブラウザーで機能を手動で検証した。
