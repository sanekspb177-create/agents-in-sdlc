`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザー上のフィルター機能を確認しました。次は、明確な QA プロセスを持つカスタムエージェントにこれらの機能をまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する方法を確認する。
- 再利用可能な quality assurance プロファイルを作成して確認する。
- QA エージェントを選択し、フィルター issue の要件に照らして報告を確認する。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザー上の動作を一貫して確認したいと考えています。カスタムエージェントを使うと、この QA プロセスを管理して、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の特化バージョンです。プロファイルには、エージェントの目的、指示、利用できるツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明します。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、要件を評価して結果を報告するために Copilot がそれらの機能をどう使うかを示します。他のカスタマイズを置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能 PR を開く前に、再利用可能な QA プロファイルを Copilot に作成させます。QA が行うチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルター機能の会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証して、テストカバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を添えて pass、fail、blocked のいずれかを報告してください。実装コードを変更する前には許可を求め、変更をコミットしたりプルリクエストを作成したりしないでください。

   まずはレビュー用にプロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA ワークフローと境界を反映したか確認します。確認だけが目的なのに、プロファイルが不完全だったり範囲が広すぎたりして、機能を変更するのを防ぎます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを読みます。`description` は必須です。`name` は省略できますが、設定するとエージェントの表示名が分かりやすくなります。
3. プロファイルの指示を読み、QA が要件を起点にし、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP を使うことを確認します。
4. QA が根拠を示し、実装コードを変更する前に許可を求め、変更をコミットしたりプルリクエストを作成したりしないことを確認します。
5. 必要な責務や境界がプロファイルに含まれていない場合は、続行する前に既定のエージェントに修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成したら、同じフィルター機能の会話を再開して QA を選択します。そうすると、すでにコンテキストに含まれている issue と計画を利用できます。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェントの一覧に表示されない場合があります。上のコマンドで有効にできます。

2. 次のプロンプトで QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   issue と計画で合意した内容に照らしてフィルター機能をレビューしてください。PR を作成する準備はできていますか。
   ```

3. QA エージェントが作業を開始します。
4. 完了したら、レポートを確認します。
