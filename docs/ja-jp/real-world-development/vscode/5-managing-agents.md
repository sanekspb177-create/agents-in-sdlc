GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ユーザーのマシンでリアルタイムに実行される作業を確認できます。すべてのツール呼び出しやファイル編集を確認し、インラインで diff をレビューして個別の変更を承認または取り消し、会話に追加のプロンプトを送って作業を調整できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムに監視する。
- 提案されたファイル編集を確認して受け入れる。
- 作業中のエージェントに追加で依頼し、ハイコントラストモードに加えてライトモードも追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードへの切り替えも追加したいとのことです。最初から新しい会話を始める代わりに、現在のセッションで作業を追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。ファイル編集は diff と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、diff がインラインで表示されます。
    - 変更を受け入れるには **Keep** を選択します。
    - 変更を元に戻してエージェントに再度作業させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したファイルの一覧を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツール呼び出しの許可を求められると、エージェントは作業を一時停止し、**Allow** を表示します。実行して問題ないコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## ライトモードの追加を依頼する

ハイコントラストモードの実装ができたら、同じ会話でライトモードの切り替えも依頼します。会話を続けることで、エージェントは前の作業で変更したコンポーネント、スタイルの方針、ローカルストレージの使い方などのコンテキストを保持します。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

    ```plaintext
    よくできました。次にハイコントラスト切り替えの隣にライトモードの切り替えも追加してください。ライトモードも同じ方法で実装し、設定をローカルストレージに保存して、同じ UI 領域から操作できるようにしてください。ユーザーがハイコントラストとライトモードを個別に有効にできるようにしてください。
    ```

2. エージェントはすでに行った変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードと同じように、新しい編集を確認します。各 diff で **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合（たとえば、切り替え UI を意図しない形で再構成しようとする場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すより短時間で調整できます。追加のプロンプトを使って、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」のように変更を依頼したり、「トグルを 3 つにせず、ライトモードを既存の設定パネルに追加してください」のように方向を修正したり、「両方のトグルにキーボードショートカットも追加してください」のように範囲を広げたりできます。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. 変更されたファイルをいくつか開き、diff を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して誘導しました。ファイル編集を確認して受け入れるか取り消し、コンテキストを保持したまま追加プロンプトを送信して作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を受け入れるか取り消す。
- 追加プロンプトで進行中のセッションを誘導する。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
