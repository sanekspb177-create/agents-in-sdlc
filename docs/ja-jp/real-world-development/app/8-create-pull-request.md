フィルター機能の実装、指示の更新、スキルの更新、quality assurance (QA) プロファイル、テストを 1 つのブランチに保存しました。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしました。今回は **Agent Merge** に PR の処理を任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントをいくつかの PR に分けます。ワークショップを簡潔に進めるため、フィルター機能と品質ワークフロー全体を 1 つのセッションとブランチで進め、そのすべてをこの PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージのライフサイクルを自動化する方法を学ぶ。
- 機能 PR 全体と検証の証拠を確認する。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認する。

## シナリオ

フィルター機能のワークフロー全体を通じて、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys は、マージの許可を開発者の管理下に置きながら、PR の残りの作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするための残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要な場合のリベースなど、マージを妨げている問題に対処します。GitHub で許可され次第マージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストがマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge に任せることもできますが、コードの編集とマージには明示的な許可が必要です。マージ権限を与える前に、許可される操作と作業を確認してください。

## Agent Merge で PR を管理する

コードを作成してレビューしたら、Agent Merge に PR のプロセスを管理させます。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンの選択だけでは始まりません。

Agent Merge が開始され、次の処理を行います。

- タイトルと説明を付けてプルリクエストを作成する。
- issue からセッションを開始した場合は、説明本文で関連する issue を参照する。
- リベースを行うか、ターゲットブランチとのマージ競合に対処する。
- CI を監視し、すべてのチェックが成功することを確認する。
- 他の開発者や Copilot code review からのフィードバックを確認し、コメントを解決する変更を加える。
- 必要に応じて、すべてのチェックが成功した後に PR を自動でマージする。

すべての条件が満たされたら、Agent Merge に PR もマージさせます。

5. マージを許可する前に、PR の差分と検証の証拠を確認します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のように明示して、エージェントにマージを依頼します。

    ```plaintext
    必須のチェックと承認がすべて成功したら PR をマージしてください。リポジトリの保護を回避しないでください。
    ```

9. 進行状況を確認し、報告されたブロッカーに対処します。次に進む前に、PR の状態が **Merged** であることを確認してください。マージ権限を有効にしたことやエージェントが実行中であることだけでは、マージ完了の確認になりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行する前に、それらのブロッカーに対処してください。
